玩家意图Player intent→ LLM→ 17 个 MCP 工具17 MCP tools→ OpenRA 引擎逐帧执行OpenRA engine, tick by tick
  • 17 个工具 + 2 个小队原语，覆盖钳形攻势、佯攻偷袭、路线约束、分时进攻等 10 类战术。

用 0.5B 小模型替代大模型 APIReplacing the LLM API with a 0.5B model

用大模型生成约 1,000 条「中文指令 → JSON 命令」数据，对 Qwen2.5-0.5B 做 QLoRA 微调，让一个本地小模型就能把玩家的话翻译成引擎可执行的命令，不再依赖付费 API。

I used an LLM to generate ~1,000 “Chinese command → JSON order” pairs and QLoRA-fine-tuned Qwen2.5-0.5B, so a small local model can translate what the player says into engine-ready orders without a paid API.

100%输出合法 JSONvalid JSON
99%意图识别准确intent accuracy
~0.8GB本地推理显存memory to run
  • 分数高 ≠ 能用：v1–v3 分数不低，但对准的是已废弃的指令格式，约 80% 输出引擎不认；v4 改为对准真实格式，输出全部可执行。
  • 数据配比是关键：不控比例，少见指令学不会；全部压平，常见的「进攻」又变差；常见类上限约为少见类 2 倍时两头兼顾。
  • High score ≠ usable: v1–v3 scored well against a deprecated command format, so ~80% of outputs were rejected by the engine; v4 targets the live format and every output executes.
  • Class balance is the lever: no cap starves rare commands, an equal cap hurts the common “attack”; capping the common class at ~2× the rare ones gets both.

v4 版本，100 条留出指令评测；完整命令逐字一致率 50%，剩余差异多为兵种筛选的细微分歧。

v4, evaluated on 100 held-out commands; 50% match the reference order exactly, most misses are minor unit-filter differences.
